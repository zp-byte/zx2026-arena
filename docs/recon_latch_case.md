## 结论前置

**定谳：投完机不是病人，是传染源。** `_on_payload_done` 返航爬升悬停点（drop 东偏 1.2m、cruise_z 1.2）距平台悬停点 3D 仅 1.26m，落在 Boids 分离半径 sep_radius=1.5m 场内——done 机悬停 30-60s 等返航错峰期间，以 ~0.56 m/s 级分离推力持续推挤后续降机/悬停机，伺服拉回与推力形成极限环（horiz 0.29-1.04 振荡），`arrived ∧ settled` 无法同帧闩住 → 入场门饿死 → 45s 腿超时跳平台 → RECON 拉长至 161-171s。

**激活机制：潜伏病灶被杨树林低巡航体制踩响。** 旧配置 cruise_z=1.8 时 done 机悬停点 3D 距离 = √(1.2²+1.0²) = **1.56 > 1.5**，场外贴线（余量仅 0.06）；杨树林 `heights.cruise_z: 1.8→1.2`（冠下平飞，09-23 定制）后 3D = √(1.2²+0.4²) = **1.27 < 1.5**，跨过阈值。老场景从未出病、poplar 局必出病，一个数字解释。

**结构性根因：同一个 1.2m，run11 只修了一条路。** run11 法证已定谳"1.2m 等待位把悬停机顶到 0.54 平衡点"并把 RECON 让位等待位 `_wait_pos` 改成 +2.2m+y 散点；但 `_on_payload_done` 的返航爬升悬停点（:587）保留东偏 1.2m——设计目标不同（防"done 即放行"窗口的爬升柱×下降柱垂直交错相撞），防撞目标达成了，但 1.2m 错开不足以出分离场：**赢得了相撞，输给了推挤**（W2 风险再分布、dam v2 暴露时长同款形态第四次复刻）。
